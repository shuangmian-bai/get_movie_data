# 系统整体设计：多源接入 + 可扩展去广告引擎 + 缓存机制

## 1. 背景与目标

本项目把多个影视站点统一接入成一套检索、详情、播放地址接口，并在播放链路上提供
**插件化去广告处理**。本设计文档从整体视角说明三件事如何协同工作：

1. **多源接入**：新增站点只写插件，不改框架，统一输出标准结构；
2. **可扩展去广告引擎**：广告检测与去水印都是插件，按站点自由组合，
   应对「不同源的广告类型不一样」这一核心约束；
3. **缓存机制**：数据源抓取与去广告处理两级缓存，减少对源站的重复请求与重复计算，
   **降低服务器压力**。

### 1.1 要解决的问题

| 问题 | 表现 |
|---|---|
| 站点差异大 | 每个站点接口、字段、结构各不相同，无法用一套解析逻辑覆盖 |
| 广告形式各异 | 有的源是片头插播（整段广告），有的源是画面水印/角标，有的源两者都有；词表与阈值也各不相同 |
| 重复请求源站 | 同一关键词、同一详情、同一播放地址被反复抓取，源站压力与延迟双高 |
| 重复处理 | 同一部片的去广告处理被重复执行（下载分片、抽帧、OCR、去水印全是重活） |
| 防盗链拦截 | 前端直拉源站常被 Referer/Cookie 校验拦截，需要统一出口 |

### 1.2 设计目标

- **插件化**：数据源、检测器、去水印器三类插件均可插拔，新增能力不改引擎；
- **统一出口**：对外只暴露一套标准接口与标准数据模型，站点差异收敛在插件内部；
- **按源组合**：去广告的检测器/去水印器组合按站点（base_url）自由编排，未匹配走默认；
- **复用优先**：一切可复用的结果（搜索/详情/播放/整片/分片）先查缓存再执行；
- **失败降级**：检测、下载、OCR 任何一步失败都不阻断播放链路，宁可漏报不可误杀；
- **低耦合**：模块之间不互相 import，统一在应用层（main.py / web/）编排汇总。

### 1.3 设计原则

- **领域能力下沉**：数据源解析、去广告处理是「换一个父项目仍成立」的能力，各自成模块；
  调度、编排、缓存组合属于应用层；
- **契约唯一真源**：插件契约、数据模型、接口定义各只在一处完整定义，其余处引用；
- **配置即文档**：所有可调参数走环境变量（前缀 `MEDIA_SOURCE_*` / `AD_FILTER_*`），
  默认值即当前实测值，见第 8 节。

## 2. 总体架构

### 2.1 分层结构

```
前端 / 外部调用方
   │  HTTP
   ▼
┌─────────────────────────────────────────────────────────────┐
│ 应用层：main.py（编排） + web/api.py（REST API + 缓存编排）    │
└─────────────────────────────────────────────────────────────┘
   │                                    │
   │ 数据源链路                          │ 播放链路
   ▼                                    ▼
┌──────────────────────────────┐  ┌──────────────────────────────┐
│ 数据源层：media_source         │  │ 去广告层：ad_filter           │
│  ├─ 插件管理器（扫描/限流/隔离）│  │  ├─ 引擎（m3u8 解析→检测→   │
│  ├─ 字段映射引擎（白名单过滤） │  │  │   丢弃/去水印/代理→重写）  │
│  ├─ 标准数据模型（Pydantic）   │  │  ├─ 检测器插件（可扩展）      │
│  └─ 站点插件 plugins/*         │  │  ├─ 去水印器插件（可扩展）    │
└──────────────────────────────┘  │  └─ 代理（长驻连接池+防盗链）  │
                                  └──────────────────────────────┘
   │                                    │
   ▼                                    ▼
┌──────────────────────────────────────────────────────────────┐
│ 缓存层：项目根 cache/                                        │
│  ├─ {站点}/            数据源缓存（FileCache，JSON，TTL 分级）│
│  └─ ad_filter/         处理结果（index.m3u8 + 去水印分片 + meta）│
└──────────────────────────────────────────────────────────────┘
```

### 2.2 依赖方向

- `main.py` / `web/` → `media_source`、`ad_filter`、`frontend_loader`（单向）；
- `ad_filter` **不 import** `media_source`，`media_source` **不 import** `ad_filter`；
  两者通过应用层传递的 `base_url` 与标准模型解耦；
- `ad_filter.proxy` 只依赖自身配置与 httpx，不依赖其它模块；
- 插件只依赖框架基类与工具，**禁止**反向依赖应用层。

### 2.3 一次完整播放请求的链路

```
GET /api/search?key=仙逆&base_urls=...
   └─ 缓存层命中 → 直接返回；未命中 → 插件管理器并发搜索各源 → 回填缓存

GET /api/play?base_url=...&link=...&episode_index=1
   └─ 详情/播放地址走缓存 → 得到上游 m3u8

POST /api/ad_filter/process { m3u8_url, base_url }
   └─ 按 base_url 取检测器+去水印器组合 → sid 内容寻址幂等复用
   └─ 未处理过：下载 m3u8 → 逐分片下载/检测 → 丢弃/去水印/代理 → 重写 m3u8 → 落盘
   └─ 返回 { sid, playlist_url }

GET /ad_filter/{sid}/index.m3u8 → 前端播放
   └─ 分片二选一：file/{name}（去水印后的本地文件）或 proxy/{name}（代理透传上游）
```

## 3. 多源接入设计

### 3.1 插件契约

数据源插件继承抽象基类 `MediaSourcePlugin`（media_source/base.py），必须声明：

| 声明项 | 内容 |
|---|---|
| 类属性 | `base_url`（站点标识，唯一路由键）、`source_name`、`source_desc` |
| 映射模板 | `search_mapping` / `info_mapping` / `play_mapping` / `episode_mapping` |
| 抽象方法 | `_raw_search(key)` / `_raw_get_info(search_item)` / `_raw_get_play_url(media_info, episode_index)` |
| 可选钩子 | `_raw_search_page(key, page)`（支持分页的站点覆盖，page 从 1 开始） |

**契约纪律**：`_raw_*` 只返回**原始 dict / list[dict]**，禁止返回 Pydantic 模型、
禁止字段过滤。基类公开方法把原始数据交给映射引擎，输出标准模型，并自动注入
`base_url` 与映射分集列表。

插件包固定 4 个文件（参考 media_source/plugins/template）：

```
plugins/<站点>/
├── __init__.py      # 导出插件类
├── constants.py     # 站点 URL、请求头、固定参数
├── parser.py        # 纯异步函数，返回原始字典
└── main.py          # MediaSourcePlugin 子类 + 映射模板 + _raw_* 实现
```

### 3.2 字段映射引擎

模板语法：`"标准字段": "{站点原始字段} | default:默认值"`（media_source/mapping.py）。

- **白名单过滤**：只输出模板声明的字段，站点多余脏字段全部丢弃；
- **取值优先级**：原始字段存在则取值，不存在回退 `default:` 值（`ast.literal_eval` 解析），
  再回退 Pydantic 模型默认值；
- **统一结构**：所有站点数据经过映射后结构完全一致，前端与接口无需感知站点差异。

### 3.3 插件管理器

`PluginManager`（media_source/plugin_manager.py）在导入时用 `pkgutil` 扫描
`media_source/plugins/*`，跳过 `template` 与 `_deprecated` 目录。

| 能力 | 说明 |
|---|---|
| `get_supported_sources()` | 返回已加载的源列表（`SourceMeta`） |
| `get_plugin_instance(base_url)` | 按 base_url 路由到插件，无匹配抛 `PluginNotFoundError` |
| `batch_search(key, base_urls, start, count, page_concurrency)` | 多源并发搜索，信号量限流（`MAX_PLUGIN_CONCURRENCY`）+ 单源异常隔离 |

**全局分页语义**：多源时 `start`/`count` 是全局分页——各源先抓前 `start+count` 条，
按 base_url 字典序合并后整体切片，每页是「所有源整合后的总数」而非每源各 count 条。

**双层异常策略**：批量模式容错（单源失败只记日志，返回有效数据）；单源模式严格
（异常直接抛出，便于精准处理）。

### 3.4 标准数据模型

Pydantic V2（media_source/models.py，`coerce_numbers_to_str=True`）：

| 模型 | 用途 | 关键字段 |
|---|---|---|
| `SourceMeta` | 数据源元信息 | source_name / base_url / source_desc |
| `SearchItem` | 搜索结果条目 | name / link / type / year / cover / desc / base_url |
| `EpisodeItem` | 分集条目 | name / index / link |
| `MediaInfo` | 影视详情 | 基础字段 + episodes 分集列表 |
| `PlaySource` | 播放地址 | url / type / headers |

### 3.5 新增数据源流程

1. 复制 `plugins/template` 为 `plugins/<站点>`；
2. 按 3.1 的 4 文件结构实现：constants 定接口、parser 出原始 dict、main 定义映射与 `_raw_*`；
3. 重启项目，管理器自动扫描加载，`GET /api/sources` 即可见；
4. 完整分步教程见 media_source/docs/PLUGIN_DEV_GUIDE.md。

## 4. 可扩展去广告引擎设计

### 4.1 广告类型与处理动作

引擎对每个 ts 分片输出三类判定（ad_filter/models.py `DetectionResult.ad_type`）：

| 判定 | 含义 | 处理动作 | 输出 |
|---|---|---|---|
| `none` | 正常分片 | 不处理 | 引用 `proxy/{name}`，本服务代理透传上游 |
| `full` | 全广告（整段插播） | **丢弃** | 从重写后的 m3u8 移除该分片块 |
| `watermark` | 水印广告（角标/水印） | **去水印** | 处理后落盘，引用 `file/{name}` |

**本地只保存修改了画面的分片**（去水印后的），正常分片不落盘，省磁盘。

### 4.2 插件抽象

**Detector（检测器）**（ad_filter/detector/base.py）：

```python
class Detector(abc.ABC):
    name: str = ""

    @abc.abstractmethod
    async def detect(self, segment_path: str, segment_url: str) -> DetectionResult:
        """检测一个已下载到本地的 ts 分片，返回 none / full / watermark + 水印区域"""

    def fingerprint(self) -> str:
        """配置指纹：纳入 sid 复用键，配置变化触发重新处理。默认返回 name。"""
```

**Remover（去水印器）**（ad_filter/remover/base.py）：

```python
class Remover(abc.ABC):
    name: str = ""

    @abc.abstractmethod
    async def remove(self, segment_path: str, boxes: List[Box], out_path: str) -> str:
        """对命中水印的分片做画面处理，输出处理后的分片文件路径。"""
```

插件**不携带 base_url**，站点 → 插件组合由应用层编排（见 4.3）。

**内置实现**：

- `OcrDetector`：opencv 均匀抽 `AD_FILTER_OCR_FRAME_COUNT` 帧 → rapidocr 识别文字（带 bbox）
  → 命中违规词表（`AD_FILTER_OCR_BLOCKWORDS`）→ 分类：命中帧占比 ≥ `FULL_FRAME_RATIO`
  且命中区域面积占比 ≥ `FULL_AREA_RATIO` 判 full，否则判 watermark（bbox 合并重叠 +
  向外扩展 `WATERMARK_MARGIN`）；未命中/抽帧或 OCR 失败一律 none（放行）；
- `DelogoRemover`：opencv `inpaint`（Terea 算法）填补水印区域 + PyAV 重编码写回 .ts
  （视频重编码 + 音频 copy）。inpaint 是通用去水印近似，可替换为其它算法。

### 4.3 站点 → 插件组合：不同源广告类型不一样的解法

不同源的广告形式、词表、阈值、检测手段各不相同，设计上用**组合编排**而非写死：

- 应用层（main.py）维护 `AD_FILTER_PIPELINES: Dict[base_url, (检测器列表, 去水印器)]`；
- 调用方只传 `base_url`，引擎按站点取组合，**不感知站点细节**；
- 未匹配的站点走 `AD_FILTER_DEFAULT` 默认组合；
- 组合经 `ad_filter.api.set_pipeline_getter(...)` 注入，引擎在运行时按站点解析。

当前编排（main.py）：

```python
AD_FILTER_PIPELINES = {
    "https://www.cupfox7.com": ([OcrDetector()], DelogoRemover()),
    "https://www.qqll.cc": ([OcrDetector()], DelogoRemover()),
}
AD_FILTER_DEFAULT = ([OcrDetector()], DelogoRemover())
```

**不同源广告类型不同时的组合策略**（本设计的核心扩展点）：

| 差异维度 | 组合方式 | 实例 |
|---|---|---|
| 违规词表不同 | 检测器实例注入不同词表/阈值 | 源 A 词表=博彩类，源 B 词表=平台品牌类，各建一个 OcrDetector 实例 |
| 检测手段不同 | 检测器列表换一个/加一个 | 某源广告是滚动字幕 → 专用字幕检测器；某源是静态角标 → OCR 即可 |
| 广告形态不同 | 检测器判 full/watermark，引擎动作固定 | 某源全是片头插播 → 命中即 full 丢弃；某源是水印 → 命中即 watermark 去水印 |
| 去水印算法不同 | 去水印器换一个 | 某源水印在复杂背景 → 换更强的去水印实现，DelogoRemover 可替换 |
| 无广告源 | 空检测器列表或跳过处理 | 组合给 `([], None)` 或引擎层短路，直接透传 |

> 词表/阈值等站点私有参数属于插件配置，通过环境变量或实例参数注入，
> 不写进引擎代码。新增站点时只需在 `AD_FILTER_PIPELINES` 加一行组合。

### 4.4 引擎主流程

`engine.process(req, detectors, remover)`（ad_filter/engine.py）：

```
1. sid = md5(m3u8_url + headers + 检测器指纹)[:16]        # 内容寻址
2. per-sid 锁 + 双重检查：已有 index.m3u8 → 幂等复用，直接返回
3. 下载 m3u8（Master 选最高带宽 variant；相对/绝对分片 URI 统一 urljoin）
4. 逐分片（信号量 SEGMENT_CONCURRENCY 限流并发）：
      下载到临时目录 → 检测器链顺序 detect（首个非 none 即返回，异常放行）
        ├─ full      → 丢弃（重写 m3u8 时跳过该块）
        ├─ watermark → remover.remove() 落盘 {sid}/{name}，引用 file/{name}
        └─ none      → 不落盘，引用 proxy/{name}，记入 seg_map（分片名→上游URL）
5. 原子写 index.m3u8（追加 EXT-X-ENDLIST，点播语义）+ meta.json（含统计）
6. 返回 { sid, playlist_url: /ad_filter/{sid}/index.m3u8, stats }
```

**检测器链语义**：`_detect_any` 顺序跑检测器列表，返回首个非 none 的结果；
全部 none 或检测器抛异常 → 放行（none）。「宁可漏报不可误杀」贯穿始终。

### 4.5 代理与防盗链

`ad_filter/proxy.py` 用**模块级长驻 httpx 连接池**（懒加载，`close_proxy` 在服务退出时关闭）：

- 正常分片统一经本服务代理转发，携带防盗链头（Referer/Cookie 由请求 headers 透传）；
- 复用 TCP 连接，避免每次分片重建连接的开销；
- 代理只做流式转发，不落盘、不处理。

### 4.6 失败容错清单

| 失败点 | 行为 | 理由 |
|---|---|---|
| 检测器异常 | 该检测器跳过，继续下一检测器；全失败放行 | 不阻断播放链路 |
| 分片下载失败 | 降级为正常分片走代理 | 不丢内容、不误杀 |
| OCR 缺失/识别失败 | 放行（仅失去检测能力） | 识别是尽力而为 |
| 加密分片（AES-128） | 抽帧失败自动放行走代理 | opencv/PyAV 无法解加密分片 |
| rapidocr 首次加载慢 | 模型常驻内存，后续复用 | 首次请求稍慢，之后稳定 |

## 5. 缓存机制设计

缓存分两级：**数据源缓存**（抓得少）与**去广告处理缓存**（算得少）。
两者统一落在项目根 `cache/` 下（见 README 的缓存目录约定），各目录可用环境变量覆盖。

### 5.1 数据源缓存（FileCache）

media_source/cache.py，文件缓存 + 全局单例 `file_cache`：

| 项 | 设计 |
|---|---|
| 命名空间 | 按 `base_url` 规范化分目录（`cache/{站点}/`），不同站点互不干扰 |
| 缓存文件 | JSON：`{"ts": 写入时间, "expires": 过期时间, "data": 数据}` |
| key 设计 | 业务参数键，如 `search:仙逆:0:20`、`info:<详情链接>`、`play:<分集链接>`；内部 MD5 成文件名，规避路径非法字符 |
| 写入 | 原子写：`.tmp` → `os.replace` |
| 读取 | 未命中或过期返回 None，过期文件惰性删除 |
| 并发穿透防护 | `get_or_fetch` 内 per-key `asyncio.Lock` + 双重检查：同一 key 并发请求只有一个真正爬源，其余等待锁后复用 |

**TTL 分级**（影视数据时效长，按天级失效）：

| 数据类型 | 默认 TTL | 配置项 |
|---|---|---|
| 搜索结果 | 7 天 | `MEDIA_SOURCE_SEARCH_TTL` |
| 详情信息 | 30 天 | `MEDIA_SOURCE_INFO_TTL` |
| 播放地址 | 7 天 | `MEDIA_SOURCE_PLAY_TTL` |

**缓存编排在应用层**（web/api.py）：`_search_one` / `_search_batch` / `_get_info` /
`_get_play` 四个辅助函数统一封装「先查缓存、未命中才爬、爬完回填」，
插件框架本身不感知缓存。多源搜索的缓存 key 还包含源组合维度（`base_urls` 排序拼接），
不同源组合不共享缓存。

### 5.2 去广告处理缓存

**会话级（已实现）**：sid 内容寻址（见 4.4）。同一部片 + 同一套检测器配置 → 同一 sid
→ 已有 `index.m3u8` 直接复用，跨请求、跨会话幂等，不重复下载分片、不重复检测去水印。

**分片级（演进方向，设计见 ad_filter/DESIGN.md，待实现）**：

- 复用粒度从「整片」细化到「分片」：键 `md5(分片URL + 检测器指纹)`；
- m3u8 秒回 + 动态分片端点 `GET /ad_filter/{sid}/segment/{name}`：
  未处理分片触发同步检测（或降级先透传后替换），已处理分片直接命中缓存；
- 播放位置驱动的优先级调度（seek 优先 + lookahead 预取），只处理被播放/预取的分片，
  进一步压掉无用的检测与下载。

### 5.3 缓存与降压的量化关系

| 场景 | 无缓存 | 有缓存 |
|---|---|---|
| 同一关键词重复搜索 | 每次全量爬所有源 | TTL 内 0 次爬虫 |
| 同一详情反复查看 | 每次重爬详情页 | TTL 内 0 次爬虫 |
| 同一部片重复播放 | 每次重下全部分片 + 全量 OCR + 去水印 | sid 命中，0 次处理 |
| 多人看同一部片 | 每人各处理一次 | 后到者全部命中缓存 |

## 6. 降低服务器压力策略汇总

| 压力来源 | 策略 | 落点 |
|---|---|---|
| 重复搜索/详情/播放请求 | TTL 分级文件缓存 + 并发穿透防护 | media_source/cache.py、web/api.py |
| 多源并发打爆源站 | 插件批量并发限流（`MAX_PLUGIN_CONCURRENCY`）+ 翻页并发控制（`PAGE_CONCURRENCY`） | media_source/plugin_manager.py、config.py |
| 前端分页全量翻 | 只抓覆盖 `[start, start+count)` 的分页，不抓全量 | plugin_manager.search_page |
| 重复去广告处理 | sid 内容寻址幂等复用 | ad_filter/engine.py |
| 逐分片重复下载/检测 | 分片级缓存 + 按需调度（演进，见 DESIGN.md） | ad_filter（待实现） |
| 代理连接开销 | 长驻 httpx 连接池复用 TCP | ad_filter/proxy.py |
| OCR/检测算力过载 | OCR 并发上限（`OCR_CONCURRENCY`）+ 失败放行降级 | ad_filter/config.py |
| 整片全量处理浪费 | 按需处理 + 预取窗口（演进，见 DESIGN.md） | ad_filter（待实现） |
| 源站防盗链拦截 | 统一代理出口，防盗链头透传 | ad_filter/proxy.py |
| 磁盘占用 | 只落盘修改了画面的分片，正常分片代理不落盘 | ad_filter/engine.py |

## 9. 扩展指南

### 9.1 新增数据源

复制 `plugins/template` → 实现 4 文件 → 重启自动加载。详见
media_source/docs/PLUGIN_DEV_GUIDE.md。

### 9.2 新增检测器

1. 在 `ad_filter/detector/` 下建插件，继承 `Detector`，实现 `detect()`；
2. 在 `fingerprint()` 返回稳定配置指纹（纳入 sid 复用键）；
3. 在 `main.py` 的 `AD_FILTER_PIPELINES` 中把目标站点的检测器列表换成/加上新检测器；
4. 检测器异常自动放行，无需额外容错代码。

### 9.3 新增去水印器

1. 在 `ad_filter/remover/` 下建插件，继承 `Remover`，实现 `remove()`；
2. 按站点在 `AD_FILTER_PIPELINES` 中指定对应去水印器；
3. 引擎只调用 `remove()` 并落盘，算法细节完全封装在插件内。

### 9.4 新增广告类型

1. `DetectionResult.ad_type` 增加新类型值（如 `banner`）；
2. 引擎处理分支增加对应动作（复用丢弃/去水印/代理三动作，或新增动作）；
3. 检测器按新类型返回判定；
4. 若需要新的处理动作（如「模糊」而非「去除」），在引擎 `_handle` 中按 ad_type 分发。
类型判定与处理动作解耦，新增类型不破坏既有三类语义。

### 9.5 新增站点的去广告组合

在 `AD_FILTER_PIPELINES` 加一行：`"<base_url>": ([检测器列表], 去水印器)`。
词表/阈值不同的站点各自建独立检测器实例注入，互不影响。

## 10. 已知限制与演进方向

| 项 | 现状 | 演进方向 |
|---|---|---|
| 分片级缓存与按需调度 | 整片全量同步处理 | 分片级缓存 + 快速起播 + seek 优先 + 预取窗口（ad_filter/DESIGN.md，待实现） |
| 加密分片（AES-128） | 抽帧失败自动放行走代理 | 可选解密后检测（需评估密钥来源与成本） |
| 缓存清理 | TTL 惰性删除 | 可加定时清理任务，避免过期文件长期占盘 |
| 状态驻留 | per-sid 锁、（演进后的优先级队列）在内存 | 多实例部署时需外置化（当前为单实例部署） |
| 代理带宽 | 正常分片经服务转发，占出口带宽 | 这是省盘的取舍；量大时可评估直连放行策略 |
