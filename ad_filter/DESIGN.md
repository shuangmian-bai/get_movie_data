# ad_filter 按需去广告调度（已实现）

## 背景与问题

早期实现是**全量同步处理**：一次性下载所有分片 → 全部检测 → 全部处理完 → 才返回 m3u8。
三个问题：起播久（全量 OCR 可能几分钟）、seek 无效（无论看哪里都按顺序从 0 处理）、
复用粒度粗（整片一个 sid，只能整片复用）。

## 目标

**快速起播 + 按需处理 + 分片级复用 + 最小开销**。

## 已实现

### 1. process 秒回

`POST /api/ad_filter/process` 只做三件事：下载并解析 m3u8（Master 选最高带宽 variant）、
生成分片清单、写 `index.m3u8`（所有分片指向动态端点 `segment/{name}`），**立即返回**。
不下载、不检测任何分片。实测整集 363 分片解析耗时约 1.3 秒。

### 2. 动态分片端点（按需处理）

`GET /ad_filter/{sid}/segment/{name}` 按分片状态返回：

| 状态 | 行为 |
|---|---|
| 已处理 + 全广告（full） | 返回一段极短空白 ts（播放器无缝跳过；比 204 兼容性好） |
| 已处理 + 水印（watermark） | 返回缓存中的去水印文件 |
| 已处理 + 正常（none） | 代理透传上游（带防盗链头） |
| 未处理 | 下载 → 检测 → 处理 → 写缓存 → 返回 |
| 处理失败 | 降级代理，不阻断播放（不写缓存，下次重试） |

### 3. 分片级内容寻址缓存

- 键：`md5(分片绝对 URL + 检测器指纹)`；
- 目录：`{OUTPUT_ROOT}/segments/{key}/`（`result.json` + 去水印文件）；
- 跨会话复用：同一分片在任何会话中只处理一次；命中后请求约 0.03 秒；
- 并发去重：per-分片锁 + 双重检查，同一分片同时只处理一次。

### 4. 后台预取（让播放跟上）

播放到某分片时，后台按顺序预取其后 `PREFETCH_LOOKAHEAD`（默认 3）个分片，
受 `PREFETCH_CONCURRENCY`（默认 2）限流。实测：首片约 5.8 秒（下载 + 检测 + 调度预取），
其后分片命中预取缓存约 0.3-0.4 秒，播放基本无等待。

### 5. 检测粒度优化

顶部条幅检测默认抽帧 5 → 3（`AD_FILTER_TOP_BANNER_FRAME_COUNT`），
单分片 OCR 耗时下降约 40%，命中判定仍为 2/3 帧。

## 与旧实现的关系

- 旧会话语义（整片 sid 复用、`file/` 与 `proxy/` 端点）保留兼容；
- 新会话的 `index.m3u8` 只引用 `segment/{name}`；
- 会话内存态可从 `meta.json` 重建（重启后仍能按需处理）。

## 未实现（可选增强）

- **播放进度上报 + seek 优先级调度**：前端上报当前分片，后端按「当前 → lookahead → 远端」
  排序预取；当前实现是「顺序预取」，seek 后由播放器重新触发，效果已可接受；
- **eager/lazy 切换**：极差网络下「先透传后替换」的降级策略；
- **磁盘清理**：分片缓存目前只增不减，可按 LRU/TTL 定期清理。

## 配置项

| 变量 | 默认 | 说明 |
|---|---|---|
| `AD_FILTER_PREFETCH_LOOKAHEAD` | 3 | 预取窗口（当前分片之后 N 个） |
| `AD_FILTER_PREFETCH_CONCURRENCY` | 2 | 预取并发数 |
| `AD_FILTER_TOP_BANNER_FRAME_COUNT` | 3 | 顶部条幅检测抽帧数 |
